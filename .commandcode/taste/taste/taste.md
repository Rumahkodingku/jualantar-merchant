# Taste
- Do not add comments to code (no block or line comments explaining behavior). Wants the code to speak for itself and the agent to just implement the work directly. Confidence: 0.85
- Communicates in Indonesian and expects responses, plans, and written artifacts in Bahasa Indonesia (written summaries, even in mixed form, are kept in Indonesian). Confidence: 0.8
- Prefers the agent to run autonomously once a plan is approved: wants permission prompts bypassed and the plan executed end-to-end without pausing for per-step confirmation. Works from an explicit phase/todo plan and expects every remaining item driven to completion ("continue until done") rather than progress reports that wait for the next go-ahead. Confidence: 0.85
- Prefers shell work done as small, explicit, single-purpose commands rather than one large compound invocation: a bulk command chaining `git mv` with multi-file `sed` rewrites was rejected, and the same work then succeeded when split into discrete steps. Confidence: 0.5
- Expects a full verification gate (typecheck, lint, test run, production build) to be run after finishing a change and the results reported before work is called done — explicitly asks to "verify everything" once the step is complete. Confidence: 0.6
- When a request is ambiguous or under-specified, wants the agent to ask clarifying questions first and offer concrete recommendations/options instead of making its own assumptions ("jangan membuat asumsi sendiri"). Confidence: 0.75
- Prefers a plan-first workflow: has the referenced spec/plan doc read and analyzed deeply first, then an explicit implementation plan drafted and approved before any code is written, rather than jumping straight into implementation. Confidence: 0.75
- Expects implementation plans to be thorough and directly executable: enumerate every file to create/modify with its rationale and responsibility, cover dependencies, regression risk and edge cases, and specify a safe implementation order. Confidence: 0.7
- Treats the actual codebase as the source of truth over spec/plan documents: wants the agent to audit the real source (and the real backend/API contract when relevant) before deciding changes, explicitly flag any discrepancies between the plan doc and the current repo, and never silently change or expand scope without approval. Confidence: 0.8
- Do not read or edit files under `node_modules` (e.g. inspecting a dependency's source to learn its API) — wants third-party package internals left untouched even when investigating how to configure a library. Confidence: 0.9
- Wants the agent to load/activate the relevant skills from the repo's `.agents/skills` directory when starting a task (e.g. frontend-design, ui-ux-pro-max, web-design-guidelines), so the resulting UI/UX is higher quality and easier for end users to understand. Confidence: 0.7
- Prefers reusing existing shared UI primitives from `app/components/ui` (e.g. using the existing `Tabs` component instead of a hand-rolled tab strip) and established in-repo patterns, rather than building custom one-off implementations or pulling in new libraries. Confidence: 0.6
